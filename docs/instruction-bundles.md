# Selected instruction bundles

An ACS Profile can select explicit Markdown files from the common source `~/.acs/instructions`. Store regular UTF-8 `.md` files there, including nested paths, then select them in the Profile's **Instructions** category. ACS never selects every file automatically. The Profile stores only `{source, relativePath}` references; source text stays in the host home.

Version 1 allows at most 64 selected files, 128 KiB per file and 1 MiB total. Paths have at most 16 components and 1,024 UTF-8 bytes. Source directories and files must be owned by the effective user and cannot be group or world writable. Symlinks, non-regular files, empty or BOM-prefixed files, invalid UTF-8, NUL and terminal control characters are refused. Tabs, LF and CRLF are preserved. A source body without a final newline remains unchanged.

Before creating a Session, ACS captures each selected file through no-follow directory descriptors, reads bounded bytes from its validated descriptor, and checks file identity and metadata around capture. The immutable captured bytes are then materialized under the Session's common instruction directory. Materialization does not reopen the host source. Generic `acs run` can consume this common material without creating Devin paths.

For Devin, ACS also writes one rule per selected file to the synthetic Session home under `.devin/rules`. Each name uses `acs-instruction-` plus the full lowercase SHA-256 of `source + NUL + relativePath`, followed by `.md`. The fixed frontmatter `---\ntrigger: always_on\n---\n` precedes the exact source bytes. Source frontmatter is body text and cannot change the generated activation. Before authentication, the contained Devin CLI must list and show every selected rule; ACS checks the exact Devin provider, projected path, always-on activation, and the observed body. The renderer trims leading and trailing whitespace and adds a display newline; ACS independently checks the exact prefixed source bytes on disk.

Workspace rules and AGENTS files remain ambient Devin configuration. ACS does not copy them into the Profile, rewrite the workspace, or claim that selected rules are the only rules Devin can discover. A pinned local CLI observation found that a `.git` marker changes the workspace root used for AGENTS discovery; non-Git workspaces can expose additional AGENTS rows. Such rows are not automatically classified as workspace inheritance. The selected-rule check verifies that each selected name appears once as an always-on Devin rule and that `rules show` reports its projected path, provider, activation and expected rendered content. It does not exhaustively enumerate or classify every ambient rule. If `~/.acs/instructions` is absent, source discovery returns an empty catalog and stored selections appear missing; an actual discovery error marks selected entries unavailable and keeps them selected for repair. These source-state labels do not establish the origin of arbitrary AGENTS rows. This is local discovery evidence; it does not prove model obedience.

The optional version-1 capability uses a canonical reference array, with an explicit empty value of `[]`. Older Profiles that omit it remain valid; unknown present versions and malformed selections fail strict admission. Exchange exports represent selected instruction sources as required symbolic source bindings. Import must bind the `acs-instructions` source locally; it does not export host paths or file bodies.
