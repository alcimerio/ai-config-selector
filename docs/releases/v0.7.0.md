# ACS v0.7.0

ACS v0.7.0 is the first release that admits qualified `linux/amd64` and
publishes that archive. macOS 26 Apple Silicon (`darwin/arm64`) with Seatbelt
remains supported. `linux/arm64`, Intel Macs, WSL, and containers stay refused.

## Linux support

- Admit qualified `linux/amd64` only (#232). The sandbox is system Bubblewrap,
  Landlock, and seccomp, with per-Session cgroup v2 containment. The host floor
  is Linux 6.12 or newer, Landlock ABI 6, Bubblewrap, unprivileged user
  namespaces, and cgroup v2 delegation. A missing prerequisite refuses the
  launch. There is no unsandboxed fallback and no switch that turns admission on
  for any other architecture.
- `acs update` on `linux/amd64` selects `acs_*_linux_amd64.tar.gz` from the
  published Release, verifies a static ELF, and refuses every other Linux
  architecture. This release publishes `acs_0.7.0_linux_amd64.tar.gz` and its
  `SHA256SUMS` row with the macOS archive.
- Enforce destination-specific loopback denial on Linux (#231). `connect`,
  `sendto`, `sendmsg`, and `sendmmsg` copy the destination and are emulated only
  when it is permitted. Loopback (`127.0.0.0/8`, `::1`, and IPv4-mapped
  `127.0.0.0/8`) is denied unless the Profile selected that port, or the
  destination is an exact host resolver on port 53. The Codex login callback may
  listen only on `127.0.0.1:1455` and `[::1]:1455`. Profiles opt in per port with
  `common.network` version 1, the same field macOS already enforces, for example
  `"network": {"version": 1, "selection": {"loopbackPorts": [11434]}}`.

## Grok Build

- Add the Grok Build target, pinned to grok 1.0.62 (#230). `acs grok` runs that
  reviewed binary inside the required sandbox. Selected Skills land in
  `~/.grok/skills`, instruction files in `~/.grok/rules`, and selected stdio MCP
  servers in the Session config. The Session config disables auto-update,
  compatibility scanners, plugins, and Grok's own sandbox. Folder trust is not
  pre-granted. A contained `grok --version` probe runs before any credential is
  copied. ACS then copies only `~/.grok/auth.json` when it is a regular file, or
  requires a selected `XAI_API_KEY`. No login is started inside the sandbox.
- Qualify that pinned binary on `linux/amd64` (#234). Qualified hosts admit only
  `grok --version` or an interactive `grok` with no extra arguments. Other
  flags, including login and `--trust`, stay rejected. `linux/arm64` stays
  closed.

## Linux performance

- Settle Sessions without a fixed sleep after the direct child is reaped (#235).
  Leader, adopted children, and cgroup membership are still all required before
  the Session is removed.
- Capture each filesystem snapshot with one non-following `statx` per path
  (#236).
- On the benchmark VM, an empty `acs run` went from about 76 ms to about 53 ms,
  and a 4000-file run from about 121 ms to about 87 ms.

## Dependencies

- Go module updates (#227, #228): Bubble Tea 2.1.0, ultraviolet (2026-10-08),
  `github.com/charmbracelet/x/ansi` 0.11.9, `golang.org/x/sys` 0.49.0,
  `golang.org/x/text` 0.43.0, purego 0.11.2, and klauspost/compress 1.20.3.
  The `x/sys` update renames Landlock `Access_fs` to `Handled_access_fs` and
  keeps the ABI 6 attribute prefix.
- Action updates (#227, #229): `actions/upload-artifact` 7.0.2,

  `ossf/scorecard-action` 2.5.0, and `github/codeql-action/upload-sarif` 4.39.0.

## Tooling

- Give the interactive native Linux recipe enough time to finish on a busy
  runner (#233). That scenario's control-socket deadline is 30 seconds. Launch
  behavior is unchanged.

## Upgrade and compatibility

Existing installations in the supported direct, user-owned regular-file layout
can use `acs update --check` and then `acs update v0.7.0`. macOS 26 Apple
Silicon installs the darwin/arm64 archive. Qualified `linux/amd64` installs the
linux/amd64 archive. Profiles that need a host-local service still opt in with
`common.network` version 1; Linux now enforces that selection. Stored Profiles
without a `grok` overlay are unchanged. For other layouts, follow the manual
upgrade and recovery guide on the `v0.7.0` tag once published.

ACS remains unsigned and unnotarized. The installer does not require `sudo`, edit
shell startup files, or change Gatekeeper settings.
