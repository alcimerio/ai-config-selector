# ACS v0.5.1

ACS v0.5.1 is a security and maintenance update to v0.5.0. The supported runtime
remains macOS 26 on Apple Silicon (`darwin/arm64`) with the system Seatbelt
backend. This release does not introduce a new Profile or exchange format.

## Security and correctness

- Upgrade `golang.org/x/text` from v0.30.0 to v0.42.0. This includes the
  v0.39.0 fix for
  [GO-2026-5970 / CVE-2026-56852](https://pkg.go.dev/vuln/GO-2026-5970). The advisory
  describes an infinite loop when Unicode normalization handles invalid UTF-8.
  The Go vulnerability scanner found an affected symbol reachable through ACS
  common Skill destination validation; that finding does not establish a
  demonstrated end-to-end exploit. The same release-target scan passes after
  the dependency update.
- Build with Go 1.27.1 instead of the Go 1.25.0 toolchain embedded in v0.5.0.
  This removes the known standard-library advisory matches reported against
  the older binary. Binary scans cannot establish that every reported
  vulnerable function was reachable.
- Update `github.com/klauspost/compress` to v1.18.7 for
  [GO-2026-5841](https://pkg.go.dev/vuln/GO-2026-5841), and select
  `golang.org/x/mod` v0.41.0 through the updated dependency graph for
  [GO-2026-6179](https://pkg.go.dev/vuln/GO-2026-6179) and
  [GO-2026-6180](https://pkg.go.dev/vuln/GO-2026-6180). These were dependency
  metadata findings: the affected packages were not imported by ACS or its
  tests, and neither module is included in the release executable.
- Restrict terminal device grants to the PTYs attached to the Session and the
  controlling-terminal alias, while preserving ownership-tracked child PTYs.
  Retain private close-on-exec descriptor pins until cleanup is proven;
  unrelated terminals receive no blanket device or ioctl permission.
- Traverse selected Skill material using pinned directory descriptors and
  no-follow child opens, validate opened objects, and create output files
  exclusively. Preserve descendant symlinks as links. The allowlisted Devin
  credential copy also validates its opened input before creating output.
  This hardening does not authenticate the initial root, snapshot concurrent
  edits, or change runtime access to copied links.
- Recover current Profile Builder callback panics through orderly terminal
  shutdown, avoiding the confirmed concurrent reader-close path. Preserve
  unknown/recovery-required save outcomes and independently confirmed commits,
  and report sanitized errors after restoring the terminal. Native race stress
  covers the reproduced panic path; this is not a guarantee about every
  internal failure in the terminal framework.
- Report accurate capability selection counts during Profile inspection,
  including a clear `configured` summary when a count is unavailable.
- Validate portable Profile syntax and relationships before resolving local
  bindings, so malformed intent is not reported merely as a missing binding.
- Share strict JSON scanning while preserving the separate validation policies
  of Profile inspection, portable exchange, and MCP intent.

## Maintenance

- Decouple common capability descriptors and Profile exchange codecs from
  provider-specific adapters without adding target activation or host access
  to syntax-only operations.
- Build with pinned Go 1.27.1 and GoReleaser 2.18.2. Contributors building from
  source need Go 1.27.1 or later; reproducing release artifacts requires the
  exact repository toolchain.
- Remove the unsupported Linux sandbox backend and its private helper path.
  This does not remove a supported release target: v0.5.0 already supported
  only macOS 26 Apple Silicon. Linux compilation remains a non-blocking source
  portability check, not a runtime support guarantee.
- Add pinned Go vulnerability checks and weekly Dependabot configuration for
  Go modules and GitHub Actions. These checks do not establish that native
  GitHub Dependabot alerts or security updates are enabled.
- Check both tagged source and the exact installed candidate with the pinned
  Go vulnerability scanner before release promotion. Scanner or database
  errors, reachable source findings, and binary advisory matches block the
  relevant gate.
- Update the pinned artifact upload/download Actions and repair Dependabot
  selection for the untagged `github.com/charmbracelet/x/vt` submodule using
  a narrow exception for the nonexistent exact `v0.1.0` submodule version.
  The dependency remains covered by vulnerability scanning.
- Reorganize the contributor, architecture, CLI, Profile, diagnostics, security,
  and recovery documentation around current behavior.

## Upgrade and compatibility

Existing v0.5.0 installations in the supported direct, user-owned regular-file
layout can use `acs update --check` and then `acs update v0.5.1`. The updater
verifies release assets and replaces only the ACS executable. It does not
migrate or downgrade Profiles, history, Sessions, or named authentication.
No automatic stored-data migration is added by this patch.

Fresh installations use the release-specific `install.sh` and
`acs_0.5.1_darwin_arm64.tar.gz` with `SHA256SUMS`. The installer refuses to
overwrite an existing executable and does not require `sudo` or edit shell
startup files. Keep a known-good compatible binary and follow the
[manual upgrade and recovery guide](https://github.com/alcimerio/ai-config-selector/blob/v0.5.1/docs/manual-upgrade-recovery.md)
when the updater's layout requirements are not met. Binary rollback is separate
from stored-data recovery.

## Integrity and validation boundary

The release pipeline scans the tagged source, builds one candidate, then scans
and validates the exact installed bytes on native macOS 26 Apple Silicon. It
attests the archive and checksum manifest before immutable publication. The
installer is byte-matched to that artifact set; it is not an attestation subject.

The scanner is pinned, but the advisory database is live. A clean result is
point-in-time evidence for the selected source/build configuration and embedded
binary versions. It does not cover unknown vulnerabilities, all external target
executables, or every possible security issue. Stripped binaries are checked
conservatively using embedded dependency/toolchain versions when symbols cannot
be recovered.

ACS remains unsigned and unnotarized. Checksums and provenance are not Apple
approval or malware review. Do not remove quarantine, disable Gatekeeper,
ad-hoc sign the binary, or weaken Seatbelt to make it run. Native automated
gates use synthetic authentication and local fixtures; their success does not
establish real-account login, hosted inference, or sustained daily use.
