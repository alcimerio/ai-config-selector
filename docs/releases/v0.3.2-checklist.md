# v0.3.2 Release Checklist

`INCOMPLETE` never means success. This document is both the pre-tag
authorization record and the template for the later public-evidence record;
the two phases must not be conflated. Do not record credentials, personal
paths, account details, signed URLs, target output, generated policies,
environment values, or raw terminal output.

## Relationship to the unpublished v0.3.0 and v0.3.1 candidates

The `v0.3.0` and `v0.3.1` tags exist remotely and are never moved, deleted, or
reused. Required native macOS lifecycle gates failed on both candidates, so
the immutable-publication policy withheld both Releases. v0.3.2 corrects the
normal-lifetime proof timeout exposed by the v0.3.1 gate and the attempt-scoped
artifact handoff exposed by its failed-job rerun. It also bounds Ubuntu package
provisioning and retries against the canonical archive when a runner mirror
stalls. The
[v0.3.0 checklist](v0.3.0-checklist.md) and
[v0.3.1 checklist](v0.3.1-checklist.md) remain historical records of those
unpublished attempts; they are not updated further and do not authorize,
create, move, or replace any tag, Release, or asset.

## Status and authorization rules

Only an `INCOMPLETE` item in one of the two explicitly labeled pre-tag sections
below blocks work before the workflow starts. An item in the tag-triggered or
public-release sections is expected to be `INCOMPLETE` before the push because
no tag workflow can exist yet; those items must not be pre-filled and do not
block local tag creation or the authorized tag push. The immutable tag push is
the sole human release authorization boundary. A later documentation PR is an
audit record only: it cannot authorize, create, move, or replace a tag, Release,
or asset.

## Auditable post-publication follow-up branch and PR

After the Release is public and immutable, create a documentation-only branch
from freshly fetched protected `main` named
`docs/v0.3.2-publication-evidence`. Update this checklist on that branch with
only public, sanitized facts: the release workflow and job URLs; each matrix
target's final outcome; public asset names, sizes, and SHA-256 values;
provenance verification results; and the immutable tag, tag-object, source,
and Release identities. Do not alter the tagged source, tag, Release, or
assets.

Create a PR from `docs/v0.3.2-publication-evidence` to `main` with a title
such as `docs(release): record v0.3.2 publication evidence`. The PR description
must link the immutable Release and workflow run, identify the public commands
used to recompute hashes and verify provenance, and state that it records—not
authorizes—the already-published release. Its diff and review provide the
auditable follow-up path for workflow URLs, target outcomes, public asset
hashes, provenance results, and immutable Release identity after publication.
