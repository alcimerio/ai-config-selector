# ACS v0.3.1

v0.3.1 documents the native process-isolation release contract for the
existing Devin and Skills Profile model. Existing Profile files and selections
remain compatible; a launch now also requires a certified host and a ready
native backend. A Profile cannot select a backend or request an unsandboxed
compatibility mode.

The `v0.3.0` tag was created and pushed but never published as a GitHub
Release: two required native macOS lifecycle gates in the four-target
candidate workflow failed, so the immutable-publication policy correctly
withheld the Release. That tag is preserved exactly as pushed and is never
moved, deleted, or reused; `v0.3.0` remains an unpublished, non-authoritative
candidate. v0.3.1 is a corrected candidate built on top of it. If its own
publication succeeds, v0.3.1 is the first published process-isolation release,
superseding the unpublished v0.3.0 candidate.

## Seatbelt lifecycle corrections

Two fixes address the native macOS lifecycle failures observed on the
`v0.3.0` candidate:

- **Authenticated exit/signal status.** macOS 26 can collapse a signaled,
  Seatbelt-supervised process into `sandbox-exec`'s generic exit status
  instead of the target's real result. A small status proxy now relays the
  target's exit code or terminating signal to ACS only after the contained
  supervisor has produced its authenticated cleanup proof, so the reported
  result matches what actually happened to the target rather than a
  sandbox-exec artifact.
- **Stable descendant settlement.** Process-table snapshots taken while a
  descendant is exiting can transiently expose it in an ambiguous state that
  is neither a stable live process nor proof of death. The cleanup observer
  now treats that transient state as inconclusive and retries within the
  existing bounded settlement window instead of either poisoning the cleanup
  proof or prematurely declaring the Session clean.

These are correctness fixes to how ACS observes and reports Seatbelt-contained
process outcomes on macOS. They do not change the process-isolation contract,
the supported matrix, or any Ubuntu/Bubblewrap behavior, and they do not
expand what containment guarantees ACS makes: the scope and limitations below
still apply in full.

## Installation

After the immutable GitHub Release is public, download the release-specific
installer, inspect it, and execute the local file. Do not pipe network content
into a shell.

```sh
release_version=v0.3.1
release_url="https://github.com/alcimerio/ai-config-selector/releases/download/$release_version"
curl --fail --location --proto '=https' --tlsv1.2 \
  --output install.sh "$release_url/install.sh"
less install.sh
sh ./install.sh
"$HOME/.local/bin/acs" version
```

The final command must print `acs v0.3.1`. The installer verifies the selected
archive against `SHA256SUMS`, validates its version and structure, and does not
use `sudo`, replace an existing `acs`, or edit shell startup files.

## Supported release matrix

The only Supported Platforms and Release Targets are:

| Host | Download target | Required backend |
| --- | --- | --- |
| macOS 26 | `darwin/arm64` | verified system Seatbelt |
| macOS 26 | `darwin/amd64` | verified system Seatbelt |
| Ubuntu 24.04 LTS | `linux/amd64` | verified signed-system Bubblewrap |
| Ubuntu 24.04 LTS | `linux/arm64` | verified signed-system Bubblewrap |

Windows, WSL, other Linux distributions, and other OS/architecture pairs are
not supported by this release. A source build reports `acs devel` and is not
release evidence or a substitute for a supported downloadable artifact.

## Process-isolation contract

The synthetic Session is configuration isolation: ACS copies selected global
Skills and the allowlisted Devin credential into a synthetic home. The Process
Sandbox is process isolation: it selects the certified native backend, validates
paths, rebuilds the environment, controls descriptors, and supervises the
target process tree. Repository-local Skills remain visible to Devin and are
not filtered by ACS.

The Process Sandbox exposes the workspace, leased Session, and Session-local
temporary directory as writable. It provides the selected executable, named
runtime inputs, and the minimum system runtime as read-only. Host home and host
Unix sockets are not mounted. The environment is rebuilt with Session-scoped
`HOME`, XDG directories, `TMPDIR`, a fixed `PATH`, and only validated terminal
or locale values; unrelated host environment values are excluded. Devin receives
only the standard terminal descriptors, while backend control descriptors are
closed before target execution.

Outbound IP networking remains available. ACS is not an egress firewall and
does not filter, approve, or log IP destinations. Terminal signals, resize,
and target exit status are preserved; descendants must settle before successful
Session cleanup. If cleanup cannot prove containment, ACS quarantines the
Session rather than declaring it removed.

## Backend and safe failure behavior

macOS selects the root-owned system `/usr/bin/sandbox-exec`. Ubuntu selects the
root-owned, non-writable `/usr/bin/bwrap` only when the installed `bubblewrap`
package, matching package architecture, packaged checksums, and the
user-namespace capability check succeed. Bubblewrap is neither bundled nor
downloaded by ACS.

On Ubuntu, first review the configured signed apt sources; an administrator may
repair the system package with:

```sh
sudo apt-get update && sudo apt-get install --reinstall bubblewrap
```

If AppArmor blocks Bubblewrap user namespaces, review and enable the narrow
`bwrap-userns-restrict` profile for `/usr/bin/bwrap`. Do not disable AppArmor,
turn off the global user-namespace restriction, or run ACS without containment.

Unsupported hosts, missing or unsafe backends, rejected policy, failed backend
verification, invalid paths/environment/descriptors, and failed Skill or
authentication preflight stop before Devin starts. Diagnostics use stable,
non-sensitive categories and omit generated policies, private paths,
credentials, environment values, raw backend output, and terminal controls.
There is no unsandboxed fallback.

## Native release evidence

Every protection claim in this note is limited to a successful four-target
native candidate gate for [issue #62](https://github.com/alcimerio/ai-config-selector/issues/62).
The [release workflow](../../.github/workflows/release.yml) builds one candidate
and sends its exact bytes—without rebuilding them—to each target. The
[native candidate contract](../../acceptance/promoted_artifact_native_test.go)
tests backend readiness; writable and denied paths including symlink escape;
environment values; descriptors; host Unix sockets; outbound IP; preflight;
descendants; and no-target fail-closed cases. The
[candidate lifecycle contract](../../acceptance/promoted_artifact_test.go)
tests terminal signals, resize, exit behavior, concurrent leases, and abandoned
Session cleanup. The Seatbelt lifecycle corrections above were made to satisfy
these same two contracts on macOS.

## Compatibility and limitations

The Profile envelope, category schemas, commands, persistence permissions, and
selected Skills contract remain compatible with earlier Profiles; no migration
is needed. That compatibility does not imply a compatible launch on an
uncertified host or without the native backend.

The signed-system Bubblewrap verification is an offline package-integrity
check, not protection from an administrator who controls both the package state
and executable. ACS supports only Devin and Skills, does not filter
repository-local Skills, permits outbound IP traffic, and has no package-manager
distribution, updater, or uninstaller. v0.3.1 macOS binaries are unsigned and
unnotarized; checksum or GitHub provenance does not provide Apple signing,
notarization, malware review, or Gatekeeper approval. The historical broad
Seatbelt prototype is feasibility history only, not a claim about a broader
production policy.

The optional authenticated real-Devin smoke is a maintainer confidence check;
it never replaces the credential-free native candidate gate. See the
[architecture](../architecture.md#v031-native-evidence-map) and
[README limitations](../../README.md#known-limitations) for the maintained
boundary and exception records.
