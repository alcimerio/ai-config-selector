# ACS v0.5.0 proposed release checklist

This checklist prepares a possible unsigned, unnotarized v0.5.0 release. It
does not record a tag, authorize a tag push, publish a release, or claim that
v0.5.0 assets exist. All evidence fields remain pending until produced for the
exact reviewed source and final tag workflow.

Never move, delete, or reuse a release tag after it is pushed. A failed cut is
fixed in source and receives a new version.

## Scope and policy

- Proposed stable version: `v0.5.0`.
- Latest published release before this cut: immutable `v0.4.0`.
- Final source commit and tree: **PENDING**.
- Comparison with v0.4.0 release notes and source: **PENDING REVIEW**.
- Supported release target: macOS 26 `darwin/arm64` with system Seatbelt.
- Linux remains a non-blocking compile observation; Intel is historical v0.4.0
  evidence only.
- Apple signing/notarization posture: intentionally unsigned and unnotarized;
  no Apple credential acquisition is required for this cut.
- Gatekeeper bypass, quarantine removal, ad-hoc signing, and Seatbelt weakening
  are prohibited workarounds.
- Planned capability release and week-long daily-use observation are separate.
  The observation is **PENDING**, must not be inferred from CI, and issue #105
  remains open.

## Documentation and migration

- [ ] Release notes accurately describe the final source delta from immutable
  v0.4.0 without changing historical release records.
- [ ] Every v0.5.0 URL is identified as future/pending until publication.
- [ ] The v0.4.0 bootstrap uses the future v0.5.0 installer because the v0.4.0
  binary has no `update` command.
- [ ] Bootstrap installs into a new empty user-owned direct directory, retains
  the old binary, verifies explicit command resolution, and does not overwrite
  an occupied destination.
- [ ] Quiescent Profile backup, explicit migration, binary rollback, stored-data
  compatibility, Session recovery, and Keychain limits are distinct.
- [ ] Unsigned/unnotarized limitations distinguish checksum byte identity and
  GitHub provenance from Apple signing, notarization, malware review, and
  Gatekeeper approval.
- [ ] Unsupported integrations and contained synthetic/native fixtures are not
  described as real provider-account experience.
- [ ] The expired historical candidate in `current-candidate-handoff.md` remains
  historical and is not presented as current or downloadable.
