# ACS v0.6.0

ACS v0.6.0 is a breaking release on macOS 26 Apple Silicon (`darwin/arm64`)
with Seatbelt. It removes legacy Profile envelopes, hardens Session cleanup and
Codex credential handling, denies sandboxed access to host-local (loopback)
services by default, and lands the full Linux sandbox stack while production
Linux launches stay disabled.

## Breaking changes

- Remove legacy Profile v1 and v2 envelopes and their migration path (#177).
  Stored Profiles must already use the single envelope. Readers still accept the
  previous envelope number 3 as an alias of version 1 (#178). Documentation no
  longer describes v1/v2/v3 wording (#179).
- Profiles that still use the old envelopes will not load. Recreate or rewrite
  them with the current Profile builder before upgrading.
- Sandboxed processes can no longer connect to host-local services over
  loopback (127.0.0.1, ::1, `localhost`) by default (#222). This blocks access
  to things like Ollama, Jupyter, local databases, dev servers and browser
  debugging ports. Profiles opt in per port with the new `common.network`
  capability (version 1), for example
  `"network": {"version": 1, "selection": {"loopbackPorts": [11434]}}`.
  Ports must be unique integers from 1 to 65535, at most 64. The ACS-managed
  Codex browser login alone still gets `localhost:1455` for its callback;
  ordinary Codex sessions do not.
  **Migration:** for each Profile whose agent needs a local service, add the
  port with the Profile builder's Network editor (or the field above), then
  check `acs explain`/`--dry-run`, which lists the allowed loopback ports.
  Profiles saved by v0.6.0 with a `network` selection are rejected by older
  ACS builds. Other 127.0.0.0/8 aliases, LAN addresses and remote hosts are not
  covered; ACS is not a general egress firewall. On Linux the field is
  accepted but not yet enforced (#223).

## Security and Session hardening

- Settle Seatbelt Session processes from the unsandboxed parent so agent
  processes do not survive the Session (#194).
- Verify the Codex `id_token` signature, issuer, audience, and account before
  persisting credentials projected from a Session (#195).
- Discard pending terminal input on exit (#181).
- Match absent exclusions without letter-case sensitivity (#182).
- Verify sandbox denials in macOS CI (#180).
- Deny loopback network access by default with explicit per-Profile ports
  (#222; see Breaking changes).

## Profile and launch

- Unified Profile builder, filesystem exclusions, transaction recovery, and a
  unified launch check (#158, #163, #161, #159).
- Faster Session open and no 5 s exit hang on unproven cleanup (#173, #174).
- Run the Devin skills and authentication preflights concurrently, the
  authentication probe in its own tracked Session with identical isolation
  (#221). On the macOS benchmark the preflight phase dropped from about 270-280 ms
  to about 175-185 ms (median). `ACS_DEBUG_TIMING` reports each preflight plus the
  overall `devin.preflights` wall-clock time.
- Reviewed target versions and tested example Profiles (#160, #175).

## Linux sandbox (production launch still disabled)

- Design and fail-closed Linux seams and portable Ubuntu 24.04 tests (#193,
  #196, #197).
- Kernel capability probe and `bwrap` provenance checks; filesystem and runtime
  authority compiled into a mount/Landlock plan; sealed Bubblewrap, Landlock
  and seccomp launcher (#205, #208, #209).
- Per-Session cgroup v2 containment with pidfds, authenticated cleanup,
  quarantine and recovery (#210, #211).
- Explicit credential providers and a hardened XDG 0600 file credential
  provider for Linux (#206, #207).
- Qualified shell and generic command recipes and locked Linux Devin and Codex
  CLI targets (#212-#214, landed via #224).
- Native Linux containment and denial gates on GitHub's ubuntu-24.04 runner
  (#215) and staged, unpublished linux/amd64 candidate artifacts (#219).
- Linux production launches remain disabled even when `acs doctor
  --check-linux-capabilities` probes pass. Ubuntu 24.04 also needs an AppArmor
  decision for unprivileged user namespaces before Linux can ship.
- Credential verification: Codex credentials from a Session are only persisted
  after `id_token` verification, which requires reaching `auth.openai.com`.

## Tooling and repository hygiene

- OpenSSF Scorecard, pinned staticcheck and actionlint, CODEOWNERS, issue forms,
  SECURITY.md, and macOS Session benchmark workflow (#199–#203, #171, #176, #184).

## Upgrade and compatibility

Existing installations in the supported direct, user-owned regular-file layout
can use `acs update --check` and then `acs update v0.6.0` after confirming every
stored Profile uses the current envelope. This release does not ship a v1/v2
migration. For other layouts, follow the manual upgrade and recovery guide on
the `v0.6.0` tag once published.

ACS remains unsigned and unnotarized. The installer does not require `sudo`, edit
shell startup files, or change Gatekeeper settings.
