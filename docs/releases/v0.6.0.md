# ACS v0.6.0

ACS v0.6.0 is a breaking release on macOS 26 Apple Silicon (`darwin/arm64`)
with Seatbelt. It removes legacy Profile envelopes, hardens Session cleanup and
Codex credential handling, and lands the first Linux foundation work while
production Linux launches stay disabled.

## Breaking changes

- Remove legacy Profile v1 and v2 envelopes and their migration path (#177).
  Stored Profiles must already use the single envelope. Readers still accept the
  previous envelope number 3 as an alias of version 1 (#178). Documentation no
  longer describes v1/v2/v3 wording (#179).
- Profiles that still use the old envelopes will not load. Recreate or rewrite
  them with the current Profile builder before upgrading.

## Security and Session hardening

- Settle Seatbelt Session processes from the unsandboxed parent so agent
  processes do not survive the Session (#194).
- Verify the Codex `id_token` signature, issuer, audience, and account before
  persisting credentials projected from a Session (#195).
- Discard pending terminal input on exit (#181).
- Match absent exclusions without letter-case sensitivity (#182).
- Verify sandbox denials in macOS CI (#180).

## Profile and launch

- Unified Profile builder, filesystem exclusions, transaction recovery, and a
  unified launch check (#158, #163, #161, #159).
- Faster Session open and no 5 s exit hang on unproven cleanup (#173, #174).
- Reviewed target versions and tested example Profiles (#160, #175).

## Linux foundations (production launch still disabled)

- Design and fail-closed Linux seams, portable Ubuntu 24.04 tests, kernel probe,
  filesystem plan, sealed Bubblewrap/Landlock/seccomp launcher, cgroup
  containment, and authenticated cleanup (#193, #196, #197, #205, #208–#211).
- Linux production launches remain disabled even when `acs doctor
  --check-linux-capabilities` probes pass.

## Tooling and repository hygiene

- OpenSSF Scorecard, pinned staticcheck and actionlint, CODEOWNERS, issue forms,
  SECURITY.md, and macOS Session benchmark workflow (#199–#203, #171, #176, #184).

## Upgrade and compatibility

Existing installations in the supported direct, user-owned regular-file layout
can use `acs update --check` and then `acs update v0.6.0` after confirming every
stored Profile uses the current envelope. This release does not ship a v1/v2
migration. For other layouts, follow the manual upgrade and recovery guide on
the `v0.6.0` tag once published.

ACS remains unsigned and unnotarized. The installer does not require `sudo`, edit
shell startup files, or change Gatekeeper settings.
